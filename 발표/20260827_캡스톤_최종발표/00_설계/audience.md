# 청중과 목적

> **여기가 발표의 시작점이다.** 슬라이드를 열기 전에 채운다.
> 여기를 건너뛴 발표는 발표자가 아는 것을 순서대로 늘어놓은 것이 된다.

## 누가 듣나

- 인원: 도시데이터 분석스쿨 최종발표 자리 — 수강생·강사진·심사자 (정확한 인원 미확인)
- 배경: 데이터 분석 숙련. 파이썬·회귀·지도 시각화는 설명 불필요.
  **일본 지리와 일본 관광통계는 모름**
- 결정권: 캡스톤 평가. 그리고 각자 자기 분석에 방법을 가져갈 수 있음

## 이미 아는 것

(설명하면 지루해지는 것. 여기 있는 것은 슬라이드에서 뺀다.)

- 회귀·결정계수·잔차의 뜻
- 로그 축·산점도·코로플레스 읽는 법
- 전처리의 고생 — 인코딩·조인·결측

→ **뺀다**: 회귀 원리 설명, 시각화 기법 자랑, 파이프라인 구조도

## 모르는 것

(설명하지 않으면 못 따라오는 것. 여기 있는 것에 시간을 쓴다.)

- 일본 지리 — 도도부현 47개가 어디에 붙어 있는지. 이시카와·에히메·돗토리의 위치
- 일본 관광통계 — 「숙박여행통계조사」의 연인원 기준, 종업원 10인 이상 시설 기준
- 한일 노선 구조 — 인천 말고 김해가 어디까지 덮는지. 홋카이도가 김해권이라는 것

→ **시간을 쓴다**: 지도로 위치 먼저 · 「비중」의 정의를 첫 슬라이드에서 못 박기

## 무엇을 하게 하려나

자기 공간분석에서 **대표점과 공간 단위를 먼저 의심하게** 하고,
앱을 열어 관심 지역의 어긋남을 직접 확인하게 함.

(`deck.yaml` 의 `목적` 과 같은 문장)

## 무엇을 경계하나

(이 청중이 반사적으로 반박할 것. 30_질의 의 재료다.)

| 반박 | 발표 안에서 어떻게 다루나 |
|---|---|
| 「접근성이 방문을 늘린다」로 요약당함 | **먼저 부정한다.** S5 에서 역인과를 내 입으로 말함 |
| 「결정계수 0.377 이면 낮은 것 아닌가」 | 설명이 목적이 아니라 **잔차가 산출물**임을 S5·S6 에서 명시 |
| 「숙박자로 방문을 대신해도 되나」 | S7 에서 당일치기 상쇄 논리, S10 에서 한계로 재확인 |
| 「도도부현은 너무 크다」 | 반박이 아니라 **발견**. S4 에서 먼저 말함 |
| 「점 하나로 홋카이도를 대표하나」 | **이 발표의 핵심 슬라이드(S8)로 승격** |
| 「부산 사람과 서울 사람이 같은가」 | S10 한계 — 국가 단위 접근성이지 개인 기준 아님 |
| 「독도가 일본 지도에 들어 있는 것 아닌가」 | S3 불릿 + 백업 슬라이드에 처리 내역 |
