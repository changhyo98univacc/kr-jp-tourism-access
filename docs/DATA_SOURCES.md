## 1. 국토교통부 항공통계 — 노선별 운항 실적

| | |
|---|---|
| 출처 | https://www.data.go.kr/data/15092526/fileData.do (공공데이터포털 → 에어포탈 「항공통계 상세조회(노선)」) |
| 기간 | 2025년 1월 ~ 12월, **월별로 따로** 조회 |
| 파일 | `[인천]2025-01.xlsx` … `[제주]2025-12.xlsx` — 4개 공항 × 12개월 = **48개** |
| 열 | `노선1(출발) · 노선2(도착) · 운항(편) · 여객(명) · 화물(톤)` |
| 획득 | 로그인 후 출발공항과 기간을 지정해 조회 → 엑셀 다운로드 |

**주의** — 내려받은 엑셀에는 **조회 기간이 어디에도 기록되지 않습니다.** 시트명은 항상 `Data`,
문서 속성에는 다운로드 시각만 남습니다. 그래서 파일명에 `[공항]YYYY-MM` 을 직접 붙여야 합니다.
이 프로젝트에서는 김해 1·2월 파일의 순서가 실제로 뒤바뀌어 있었고, 생성시각과
왕복 노선 편수 대조(김포↔김해, 인천↔김해, 제주↔김해)로 판정해 바로잡았습니다.

**운항 편수는 방향별입니다.** 인천→후쿠오카와 후쿠오카→인천이 각각 계산되므로,
왕복 1회는 2편입니다. 이 프로젝트는 출발지 기준 편수만 씁니다.

## 2. 일본 관광청 「숙박여행통계조사」

| | |
|---|---|
| 출처 | https://www.mlit.go.jp/kankocho/tokei_hakusyo/shukuhakutokei.html |
| 파일 | `estat_shukuhaku_2025_pref.xlsx` — 2025년(令和7年) 1~12월 **연 확정치** |
| 직링크 | https://www.mlit.go.jp/kankocho/content/002010340.xlsx |
| 크기·해시 | 2,554,483 B · `f248106e23d058ad9f49efd85c80ebb58a41330c1c9556f9c5453cc79ebdef50` |
| 쓰는 시트 | `参考第1表(1月)` ~ `参考第1表(12月)` — 施設所在地 47구분 × 国籍 21구분 |
| 쓰는 열 | 0열 지역(코드+이름) · 1열 외국인 연인원 숙박자수 · 2열 **韓国** |

**표기 주의** — 이 표는 **연인원(延べ宿泊者数, person-nights)** 입니다. 실인원(実宿泊者数)은
같은 통계의 다른 표에 있습니다. 이 프로젝트의 "숙박자"는 전부 연인원입니다.

**참고값(\*)** — 값 앞에 별표가 붙은 칸은 관광청이 표본오차가 크다고 표시한 것입니다.
쉼표와 함께 문자열(`*1,790`)로 들어 있어 그대로 숫자 변환하면 결측이 됩니다.
`build_data._num()` 이 별표를 떼고 숫자로 살리되 `korea_uncertain` 플래그를 남깁니다.
2025년 12개월 × 47지역 564칸 중 **17칸**이 참고값이며 앱이 해당 지역에 경고를 띄웁니다.

이 표는 **종업원 10인 이상 시설** 기준이라 소규모 숙박이 많은 지방이 과소평가됩니다.

**API로는 받을 수 없습니다.** e-Stat API(`statsCode=00601020`)에는 이 조사가 **2016년까지만**
등록되어 있습니다(32개 표 전부 갱신일 2019-03-16). 최신 자료는 위 엑셀로만 공개됩니다.

### ⚠️ 분쟁 지역 처리 — 반드시 읽을 것

**이 원자료는 영유권 분쟁 지역을 일본 영역으로 포함하고 있습니다.**

| 지역 | 원자료가 넣은 도도부현 | 링 수 |
|---|---|---:|
| **독도** | 島根県 (코드 32) | 3 |
| 센카쿠 열도 | 沖縄県 (47) | 17 |
| 하보마이 군도 | 北海道 (1) | 5 |
| 시코탄 | 北海道 (1) | 5 |
| 쿠나시리 | 北海道 (1) | — |
| 에토로후 | 北海道 (1) | 3 |

**`src/build_data.py` 의 `load_boundaries()` 가 이 링들을 제외합니다.**
좌표 경계상자로 판정하며, 실행할 때마다 무엇을 몇 개 뺐는지 콘솔에 찍습니다.

제외 근거는 두 가지입니다. **독도는 대한민국 영토입니다.** 그리고 나머지를 포함한
모든 대상은 이 분석에 아무것도 기여하지 않습니다 — 한국 취항 공항이 없고, 일본
숙박통계에도 잡히지 않으며, 10km 격자에 칸이 거의 생기지 않습니다.

이 처리를 하기 전에는 독도가 `min_area` 필터(5km² 미만 제거)에 **우연히 걸려** 지도에서
빠져 있었습니다. 의도한 처리가 아니었고, 필터 값만 바꿔도 다시 나타나는 상태였습니다.

## 5. 도도부현 대표점 — 현청 소재지

| | |
|---|---|
| 파일 | `data/reference/prefecture_capitals.csv` (**저장소에 포함**) |
| 내용 | 47개 도도부현의 현청 소재지 좌표 |
| 검증 | `build_data.capitals()` 가 모든 좌표가 **자기 도도부현 폴리곤 안**에 있는지 확인하고, 하나라도 벗어나면 실행을 중단합니다 |

기하학적 무게중심을 쓰지 않는 이유가 있습니다. 홋카이도의 무게중심은 **다이세쓰잔
산악지대**라서, 최적 도착공항이 삿포로(신치토세, 월 600편대)가 아니라 **아사히카와
(월 20~30편)** 로 계산됐습니다. 그 결과 아사히카와 노선이 쉬는 달에 홋카이도 소요시간이
**56분씩 튀었고**, 어긋남 값이 두 배로 부풀려졌습니다. 현청 소재지로 바꾼 뒤에는
12개월 내내 신치토세 경유 **337분으로 평탄**합니다.

## 재현 절차

```bash
# 1. 위 원자료를 data/raw/ 에 넣는다 (항공 48개는 파일명에 [공항]YYYY-MM 을 붙일 것)
# 2. 순서대로 실행
python src/build_data.py       # 경계 로드·분쟁지역 제외·대표점 검증 → panel.csv, routes.csv
python src/build_grid.py       # 10km 격자 3,953칸
python src/build_scenarios.py  # 출발공항별 접근성, 공항↔도도부현 배정
python src/analyze.py          # 회귀 적합 → 잔차, annual.csv

# 3. 앱
streamlit run app.py
```

**`analyze.py` 는 반드시 마지막입니다.** `build_data.py` 가 `panel.csv` 를 새로 쓰면서
잔차 열을 지우므로, 다시 돌리지 않으면 앱이 없는 열을 찾다가 실패합니다.
