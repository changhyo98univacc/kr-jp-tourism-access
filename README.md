# 한국에서 일본은 얼마나 가까운가

**한국 4개 공항에서 일본 각 지역까지의 접근성을 월별로 계산하고, 실제 한국인 방문과 얼마나 어긋나는지 보는 앱입니다.**

도시데이터 분석스쿨 최종 프로젝트 · 2025년 기준

---

## 무엇을 묻는가

일본 여행지는 "가까워서" 가는 걸까요? 그렇다면 **가까운데도 한국인이 잘 안 가는 곳**은 어디일까요?

이 앱은 두 가지를 겹쳐 봅니다.

1. **접근성** — 인천·김포·김해·제주에서 그 지역에 가장 빨리 닿는 데 걸리는 시간
2. **실제 방문** — 그 지역 외국인 숙박자 중 한국인이 차지하는 비중

그리고 둘의 **어긋남**을 지도에 그립니다.

> **인과를 주장하지 않습니다.** 수요가 있어서 노선이 생겼을 수도 있습니다(역인과).
> 이 프로젝트의 산출물은 "접근성이 방문을 늘린다"가 아니라 **불일치 지도**입니다.

## 무엇이 나왔나

- 접근성은 한국인 비중을 **상당히 잘 설명합니다** (R² 0.38, 월 고정효과 포함)
- **접근성 대비 과소방문** — 이시카와 · 후쿠시마 · 고치 · 미야기 · 오카야마
- **접근성 대비 초과방문** — 홋카이도 · 야마구치 · 돗토리 · 오이타 · 이바라키
- 히로시마는 282분으로 가까운 편인데 한국인 비중이 예측의 **0.48배**입니다
- 취항 공항 수가 **월별로 27~32개 사이에서 변합니다.** 연간 합계로는 보이지 않는 변화입니다
- 10km 격자 3,953칸의 세력권은 **연평균 인천 63.0% · 김해 32.4% · 김포 4.1% · 제주 0.5%**.
  제주는 **10~12월에만** 최적이 되고(최대 3.2%), 나머지 아홉 달은 한 칸도 가져가지
  못합니다 — 일본 대부분에서 김해가 더 가깝기 때문입니다
- 김해 세력권은 **9월에 44.1%까지 튑니다**(평소 30% 내외). 원인은 아직 확인하지 않았습니다

## 원자료부터 다시 만들기

원자료는 저장소에 없습니다(용량·저작권). `data/raw/` 에 아래를 넣고 순서대로 실행합니다.

| 파일 | 출처 |
|---|---|
| `[공항]2025-MM.xlsx` × 48 | [국토교통부 항공통계](https://www.data.go.kr/data/15092526/fileData.do) — 인천·김포·김해·제주 × 12개월 |
| `estat_shukuhaku_2025_pref.xlsx` | [일본 관광청 숙박여행통계조사](https://www.mlit.go.jp/kankocho/tokei_hakusyo/shukuhakutokei.html) 2025년 확정치 |
| `airports.csv` | [OurAirports](https://davidmegginson.github.io/ourairports-data/airports.csv) |
| `japan_pref.geojson` | [dataofjapan/land](https://raw.githubusercontent.com/dataofjapan/land/master/japan.geojson) — **분쟁 지역 포함. 아래 참고** |

**출처·해시·재현 절차는 [`docs/DATA_SOURCES.md`](docs/DATA_SOURCES.md) 에 있습니다.**

> ⚠️ 경계 원자료가 **독도를 시마네현으로**, 센카쿠와 북방영토를 일본 영역으로 담고 있습니다.
> `build_data.load_boundaries()` 가 해당 링을 제외하며, 실행할 때마다 제외 내역을 출력합니다.

```bash
python src/build_data.py       # 경계 로드·분쟁지역 제외·대표점 검증 → panel.csv, routes.csv
python src/build_grid.py       # 10km 격자 3,953칸
python src/build_scenarios.py  # 출발공항별 접근성, 공항↔도도부현 배정
python src/analyze.py          # 회귀 적합 → 잔차, annual.csv
```

**`analyze.py` 가 마지막이어야 합니다.** `build_data.py` 가 `panel.csv` 를 새로 쓰면서
잔차 열을 지우므로, 다시 돌리지 않으면 앱이 없는 열을 찾다가 실패합니다.

**무거운 계산은 전부 로컬에서 끝냅니다.** 앱은 결과 파일을 읽어 그리기만 합니다.

## 접근성 계산

```
총 소요시간 = 출입국 수속 165분
            + 비행 (대권거리 ÷ 800km/h + 이착륙 25분)
            + 지상이동 (대권거리 ÷ 60km/h)
```

출발 4개 공항 × 그 달 **실제 운항한 노선**을 모두 계산해 가장 빠른 경로를 취합니다.
노선이 없는 달은 그 공항을 후보에서 제외하므로, 계절 운항이 접근성에 그대로 반영됩니다.

## 색과 차트 규격

색은 눈으로 고르지 않았습니다. 범주형 팔레트는 검증기를 통과한 값만 씁니다
(`viz.py` 에 명령어와 결과가 주석으로 남아 있습니다).

- **범주형**(어느 공항인가) — 지도는 아무 두 색이나 맞닿을 수 있어 all-pairs 기준을
  넘겨야 하고, 기본 팔레트는 그 기준에서 3색이 상한입니다. 4색이 필요해 4번 슬롯만
  노랑→보라로 재배열했습니다. `CVD ΔE 9.2 / 일반시야 ΔE 16.3` 로 통과합니다
- **순차**(얼마나 오래) — 무지개를 쓰지 않고 파랑 한 색상으로 밝음→어두움
- **발산**(어느 쪽으로 어긋났나) — 파랑↔빨강 두 극과 중립 회색 중간점
- **이중축 금지** — 축이 다른 두 지표는 그림을 나눕니다

## 격자 접근성

도도부현 47덩어리로는 내부 편차가 보이지 않습니다. 일본 국토를 **10km 격자 3,990칸**으로
덮고 칸마다 최단 소요시간을 계산합니다. 지도를 확대할수록 의미가 있습니다.

접근성은 좌표만 있으면 계산되지만 **방문 데이터는 도도부현이 최소 단위**입니다
(한국인 숙박은 국적별 분해가 도도부현까지만 공표됨). 그래서 격자에는 접근성만 있습니다.
**공급은 연속인데 수요는 47덩어리라는 이 비대칭 자체가, 공간 단위 선택이 결과를
좌우한다는 사례입니다.**

## 한계

- **한국 안에서 공항까지 가는 시간이 빠져 있습니다.** 출발 4개 공항에 이미 도착해 있다고 가정한 국가 단위 접근성이며 개인 기준이 아닙니다. 서울 거주자에게 김해는 실제로 훨씬 멉니다
- **격자 극단값은 외딴 섬입니다.** 오가사와라 제도 등은 항공편이 닿지 않아 21시간까지 나옵니다. 지도 색은 상위 1%를 잘라 표시하며 실제 값은 마우스를 올리면 보입니다
- **지상이동이 근사값입니다.** 실제 철도·도로가 아니라 직선거리에 60km/h를 가정했습니다. 산악·도서 지역은 실제보다 가깝게 나옵니다
- **대표점이 현청 소재지 한 점입니다.** 넓은 현의 내부 편차는 담기지 않습니다
- **경계 원자료의 분쟁 지역을 제외했습니다** — 독도·센카쿠·북방영토. 제외 내역은 콘솔에 출력됩니다
- **숙박자 ≠ 방문자.** 당일치기·크루즈가 빠지고, 숙박지와 관광지가 다를 수 있습니다
- **해상 노선이 빠져 있습니다.** 부산–쓰시마 배편이 반영되지 않아 나가사키현이 실제보다 멀게 나옵니다
- 숙박통계는 **종업원 10인 이상 시설** 기준이라 소규모 숙박이 많은 지방이 과소평가됩니다
- 관광청이 별표(\*)로 표시한 **표본오차가 큰 참고값**이 12개월 중 17칸 있습니다. 앱에서 해당 지역에 경고를 띄웁니다
